## Findings considered and rejected

- Continuing agent execution after the desktop app quits: rejected for this
  version because it requires a separate daemon/service lifecycle and materially
  changes the local-first operational model. Persist activity and mark unfinished
  work as interrupted on the next launch instead.
- Unlimited simultaneous agent processes: rejected because each run starts an
  ACP harness and MCP subprocess and can create a repository snapshot. Run two
  concurrently and queue the rest.
- Keeping live activity only in frontend memory: rejected because navigating,
  remounting, or restarting the UI would lose the run history the feature is
  intended to expose.
