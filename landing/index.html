LaReview is a reviewer-first workbench. We help you understand the change, plan your review, and ship feedback that matters.

  • Plan First vs Comment Dump
  • Flow-Based Review vs File-by-File

The Workbench Philosophy

"Merge confidence, not just merge speed."

Senior engineers know that catching a bug is good, but understanding the system impact is better. LaReview is designed for the deep dive.

Inside the workbench

The review, step by step.

An illustrative payment-webhook change, from setup to actionable feedback.

01 / INPUT

Start with the right context.

Load a pull request, compare local Git refs, or paste a diff. Use the agent and checkout you already work with.

02 / REVIEW PLAN

One concern at a time.

Follow a review plan grouped by flow and ordered by risk. Keep progress visible while you work through the change.

03 / FEEDBACK

See the evidence.

Move from a finding to the code that explains it. Each thread has a concrete location, severity, and a reason to act.

04 / TEAM RULES

Make your standards explicit.

Teach the agent the requirements that matter to your team: atomic writes, retryable failures, and acknowledgment after commit.

05 / LOCAL CONTEXT

Keep the code within reach.

Link the checkout once, then start a review directly from the repository. The agent can inspect the surrounding code as it reviews.

06 / SHARE

Choose what leaves the workbench.

Select the tasks and feedback you want to share. Copy Markdown or post the selected items to the linked GitHub or GitLab review.

07 / SYSTEM FLOW

Understand the failure path.

Read the change as a system. Here, a diagram makes the unawaited transaction and skipped-retry risk visible.

08 / LEARNING

Keep the useful feedback.

Turn rejected suggestions into review preferences. Prioritize observable failures and spend less time on noise.

09 / COMMAND LINE

Start where you work.

Open a review from your terminal, load a pull request, or pipe in a diff.

$ lareview pr owner/repo#123
$ git diff | lareview
$ lareview --agent copilot

Workflow

INPUT

Input

Paste a unified diff or a GitHub/GitLab PR URL (e.g., owner/repo#123).

FETCH

Fetch

LaReview fetches data locally via the GitHub/GitLab CLI (`gh`/`glab`). No intermediate servers.

GENERATE

Generate

Your chosen AI coding agent (opencode, claude code, codex, etc.) analyzes intent and builds a task tree.

REVIEW

Review

Execute the plan. Add notes, track status, and export to Markdown.

PUSH

Push

Submit your review directly to GitHub or GitLab with auto-generated summaries.
